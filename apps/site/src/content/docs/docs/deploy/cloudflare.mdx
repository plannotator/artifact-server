Cloudflare is Artifact Server's first-class direct-cloud target. The deployment package composes the same product services as the local and external-storage runtimes with Cloudflare-native infrastructure.

| Product need | Cloudflare service |
| --- | --- |
| Application and HTTP runtime | Workers |
| Durable records | D1 |
| Artifact and staged-upload bytes | R2 |
| Provisioning and lifecycle | Alchemy |
| Hosted browser and MCP authorization | WorkOS |
| Optional private Git history | Cloudflare Artifacts |

## Deployment shape

```text
artifactserver.com        public Artifact Server home and Nimbus docs
app.example.com           trusted Artifact Server Worker
*.content.example.com     isolated artifact versions
```

The public site and a deployed Artifact Server installation are separate Workers. This keeps public documentation, authenticated application routes, `/api`, `/mcp`, and wildcard content delivery from competing for one routing and security policy.

## Operate the package

From `deploy/cloudflare`, authenticate to the approved account and use the pinned lifecycle commands:

```sh
pnpm plan
pnpm deploy
pnpm destroy
```

The configuration contract requires the Cloudflare account, application and content domains, D1 and R2 bindings, identity-provider settings, and Cloudflare-hosted Alchemy state. Read the repository's `deploy/cloudflare/README.md` before creating resources.

## Optional Cloudflare Artifacts history

Cloudflare Artifacts can keep a private Git copy of selected projects. It is off by default, and Artifact Server's D1 and R2 data remains authoritative. The integration creates one repository per artifact, mirrors immutable versions through a durable retry queue, backfills existing versions, and issues bounded read tokens for clones.

<Aside type="caution" title="Closed beta access is required">
Cloudflare Artifacts is not generally available. Request access, create one dedicated namespace for each Artifact Server environment, and review current pricing and limits before enabling a project.
</Aside>

Set `cloudflareArtifactsNamespace` in the deployment input. After deployment, open **Projects**, review the estimate, and enable Git history for each project that should be copied. Disabling preserves the derived repositories; deleting an artifact queues deletion of its repository.

Read the [operational guide](https://github.com/plannotator/artifact-server/blob/main/docs/cloudflare-artifacts.md) for namespace isolation, runtime states, clone and purge commands, copy limits, recovery behavior, and the bounded live qualification commands.
