# CI operations report — 2026-08-27

## Outcome

The selected tiered workflow meets the PR feedback target without changing the
canonical local gate or dropping release evidence:

- PRs run five stable required concerns: build/static policy, root
  unit/conformance behavior, browser behavior, Cloudflare deployment behavior,
  and macOS portability.
- `main`, nightly schedule, manual full dispatch, and future `merge_group`
  events run the complete ordered Linux `verify:iteration` command set plus
  macOS portability.
- A drift checker fails CI if the 14 full-tier commands diverge from the
  unchanged `package.json` `verify:iteration` script.
- The shared compiled artifact is built once per PR run, scoped to that run,
  checked by every consumer, and retained briefly. Full-tier evidence is
  uploaded after the run with a 14-day retention period.

No product code, conformance requirement, existing script name, or canonical
gate was changed. No test retry, shard, path filter, paid runner, or new secret
was introduced.

## Operational behavior and risk

Object-storage emulators, external-storage runtime, coverage, local packaging,
performance, Compose, Helm, and OIDC now run immediately after merge instead of
before it. A defect isolated to one of those surfaces can make `main` red until
corrected. The repository is pre-release and has no release automation behind
the job, so that window is acceptable today. If `main` becomes continuously
releasable, the next design should run the full gate on `merge_group` and
require a merge queue after its 40-minute critical path is reduced.

The shared artifact introduces upload/download service and layout failures.
Consumer entry-point checks fail closed. Fan-out also restores the roughly
514 MiB pnpm cache in four Linux jobs, increasing cache bandwidth while still
reducing job-minutes. The nightly schedule adds dependency, runner-image, and
emulator drift coverage at the cost described above.

## Repository settings

No merge queue or paid runner was enabled. After PR #11 proved the real check
names green, repository ruleset `21666975`, `main required PR-tier checks`, was
created with active enforcement on the default branch. It requires strict base
freshness and these seven contexts: the five PR-tier jobs, `Gitleaks`, and
`zizmor`. It has no bypass actors. PR #11 remained `CLEAN` and mergeable after
the change.

Exact creation call:

```sh
gh api --method POST repos/plannotator/artifact-server/rulesets --input - <<'JSON'
{
  "name": "main required PR-tier checks",
  "target": "branch",
  "enforcement": "active",
  "conditions": {
    "ref_name": {
      "include": ["~DEFAULT_BRANCH"],
      "exclude": []
    }
  },
  "rules": [
    {
      "type": "required_status_checks",
      "parameters": {
        "required_status_checks": [
          {"context": "PR / Build and static policy"},
          {"context": "PR / Unit and conformance behavior"},
          {"context": "PR / Browser behavior"},
          {"context": "PR / Cloudflare deployment"},
          {"context": "macOS portability"},
          {"context": "Gitleaks"},
          {"context": "zizmor"}
        ],
        "strict_required_status_checks_policy": true
      }
    }
  ]
}
JSON
```

Exact reversal:

```sh
gh api --method DELETE repos/plannotator/artifact-server/rulesets/21666975
```

## What needs Ramos

Nothing is required to operate this design. The nightly full tier uses local
emulators and needs no cloud credentials. Larger runners were rejected as
unnecessary for the PR target. An organization owner with `admin:org` is needed
only if exact charged Actions dollars, rather than observed rounded job-minutes,
must be audited.

## Recommended next step

Keep this shape for two weeks and review full-tier/nightly timing and failure
data. If full-gate latency becomes operationally important, implement candidate
B from the design document: produce one revision-verified attested OCI archive,
consume it across collision-free full-tier jobs, and measure cold-cache cost
before enabling a merge queue. Do not shard browser tests or add retries unless
new data shows browser behavior is the critical path or a specific race is
first fixed and filed.
